## Reusable patterns

**Adopt**: When an inverse problem reports a suspiciously clean
parameter correlation across heterogeneous fixtures, run a profile-
likelihood scan over the suspect parameter before declaring structural
degeneracy. The two diagnostics (joint-fit Hessian-derived ρ, and the
shape of the profile-likelihood curve) measure different things — joint
ρ can reflect either real non-identifiability OR an optimiser stuck in a
flat region. Profile likelihood pins down which.

**Adopt**: When a BC is supposed to represent a physical quantity at a
geometric position, and that position falls between two sensors, do
*spatial* per-timestep interpolation across the sensor array — never
nearest-sensor pick. The user feedback memo `feedback_thermodynamic_
interpolation` (2026-04-26) had already flagged this; this mission
applies the principle to a different consumer.

**Avoid**: Grading an inverse problem with a self-test (forward-solve
generates the data; inverse-solve fits it) and reporting recovery
quality as evidence the method is viable on real data. Round 1's
synthetic recovery passed cleanly because the forward solver is
internally consistent — but tells nothing about whether the model class
matches real physics. The synthetic_shallow_insertion misfit baseline
this round adds the missing third leg (model class fit on synthetic
that was NOT generated by the forward solver).
